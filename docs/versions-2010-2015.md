# 2010 (MadEvent) and 2015 (stand-alone) versions

Both versions implement the same physics: the tt̄ threshold (bound-state)
correction through the momentum-space Green function G(E, p) of
arXiv:1007.0075, applied to the full `pp -> b W+ b~ W-` (+ decays) matrix
elements. They differ in the integrator and the event generator around it.

Both ways of generating events were already used in the paper (its Sec. 3):
BASES/SPRING, and MadEvent 4.4.42. The BASES/SPRING-based stand-alone code is
older than the paper. "2015" below refers to the snapshot kept in this
repository, which has more final states than the 2010 MadEvent directories.

| | 2010: `legacy/paper-2010/` | 2015: `standalone/` |
|---|---|---|
| Framework | MadGraph/MadEvent v4.4.42 process directory | stand-alone Fortran (MadGraph II/HELAS matrix elements) |
| Integration / unweighting | MadEvent (`generate_events`) | BASES/SPRING V5.1 from the CPC Program Library (downloaded by the user; V5.0 also works) (VEGAS optional) |
| Final states | `blvblv`, `blvbjj` | `bwbw`, `bwblv`, `blvblv`, `blvbjj`, `bjjbjj` |
| Switches | compile-time `PARAMETER` in `GrnFnc_*/thr.inc` (`thr00/01/10/11.inc`) | run-time `COMMON/THR/`, set in `EG_*.f` or `topbs.nml` |
| Settings | `Cards/run_card.dat`, `param_card.dat` | `topbs.nml` (`standalone/common/steer.f`), `param_card_sm.dat` |
| PDF | built-in CTEQ6L1 | LHAPDF 6, `cteq6ll.LHpdf` = CTEQ6L1 |
| Cuts | MadEvent cuts (`ptl>10`, `abs(etal)<2.5`, `bwcutoff=15`, ...) | none by default (`ICUT=0`) |
| Output | LHE (`Events/*_unweighted_events.lhe.gz`) + banner; weight σ/N; IDPRUP 1 (singlet) / 8 (octet); b mass 5 GeV in the mass column | LHE (`events*.lhe`), BASES histograms; weight 1; one IDPRUP; mass column 0 for b; no banner. Both use IDWTUP = 3 and the same record layout |
| Run | `scripts/run_paper2010.sh` | `scripts/run_standalone.sh` |

## Switches

| Switch | Meaning | 2010 | 2015 |
|---|---|---|---|
| `IGRN` | 0: no Coulomb/bound-state correction, 1: overall correction prescription (OCP), 2: total-angular-momentum prescription (TAP) | yes | yes |
| `INR` | non-factorizable (non-resonant) diagrams: 0 none, 1 fixed-width scheme (2015 also: 2 overall-factor scheme) | 0, 1 | 0, 1, 2 |
| `ITR` | 0: naive diagrammatic separation, 1: remove the phase-space suppression in the resonant amplitude | yes | yes |
| `IKF` | 1: normalise each subprocess (gg singlet, gg octet, qq) to NLO with `KF = 1.14, 1.39, 1.16` (LHC 14 TeV) | yes | yes |

The 2010 files map as:

| 2010 file | `IGRN` | `INR` | `ITR` | `IKF` |
|---|---|---|---|---|
| `thr00.inc` | 1 | 0 | 0 | 1 |
| `thr01.inc` | 1 | 1 | 0 | 1 |
| `thr10.inc` | 1 | 0 | 1 | 1 |
| `thr11.inc` | 1 | 1 | 1 | 1 |

`scripts/run_paper2010.sh` writes any combination into `thr_user.inc`.

`ITR` and `IGRN=2` already exist in the 2010 code. They were not added in 2015.

## Green-function tables

Both versions read `grnep{1,8}{thre,high}.tbl` (colour singlet/octet,
threshold/high-energy grids) from the run directory. The tables in the
repository are those of `legacy/paper-2010/*/GrnFnc_*/`, computed for
m_t = 173 GeV, Γ_t = 1.4911 GeV and α_s(μ_B) = 0.1534. They are identical (md5)
to the ones used by the 2015 code. Other parameter sets can be produced with
`legacy/paper-2010/GrnEP_pro/` (several hours per table).

## Where the 2015 sources come from

The original 2015 working tree shared common files between the final-state
directories through symbolic links (XSym stubs on the backup). They were
resolved, and each shared file is kept once in `standalone/common/`:

| Final state | Origin |
|---|---|
| `bwblv`, `blvblv`, `blvbjj`, `bjjbjj` | `Work/TTExcl/<proc>/` |
| `bwbw` | `Work/TTExcl/Fortran/` (development tree; newer than the packaged `EG/EG_bwbw`, which used older COMMON block names) |
| `common/` | `Work/TTExcl/Fortran`, `Work/GrnEP`, `Work/Tools/{Fortran,madgraph}` |
| BASES | not included (CPC licence). The official V5.1 is used through `standalone/bases51/bases51_compat.f`. The KEK V5.0 copy of 2015 (`Tools/BASES/bases50`, with the author's `XHSAVE2`) gives bit-identical results |
| DHELAS | the MG/ME 4.4.42 copy of `legacy/paper-2010` (a superset of the 2015 copy: same routines plus fixes for negative masses and momenta along -z) |

Changes made to the 2015 sources:

- `common/steer.f` is new. It provides the optional `topbs.nml` override.
- `EG_*.f` call `STEER`/`STEERB`/`NEVSTR` at three places. Without
  `topbs.nml`, the programs behave as before.

## Cross-check of the two versions (issue #9)

`blvblv`, LHC 14 TeV, CTEQ6L1, μ = m_t, no lepton cuts. The 2010 MadEvent runs
keep only events with |m(lν) − m_W| < 15 Γ_W (`bwcutoff`, applied to the W's
declared as decay chains). The 2015 numbers are multiplied by the fraction of
their events inside the same window (0.983 at LO, 0.981 with the correction).

| `IGRN INR ITR IKF` | Channel | 2010 [pb] | 2015 [pb] | Difference |
|---|---|---|---|---|
| 0 0 0 0 | total | 7.091 | 7.063 | 0.4% |
| 1 0 0 0 | gg singlet | 1.782 | 1.772 | 0.6% |
| 1 0 1 1 | total | 9.036 | 9.53 | 5% |

An independent reference for the channel split is the on-shell LO
qq̄ → tt̄ and gg → tt̄ cross sections with CTEQ6L1
(`scripts/check/lo_ttbar.f`). They give σ(qq̄)/σ(gg) = 0.1507. The 2015
version gives 0.151.

### ITR=1

The matrix elements of the two versions are identical point by point
(`scripts/check/me_compare/`). At 200–2000 phase-space points, the ratio
|M|²(ITR=1)/|M|²(ITR=0) agrees exactly. The difference with `ITR=1` comes from
how MadEvent integrates it.

- `ITR=1` multiplies the resonant amplitude by `CORR`. In the 2010 code,
  `CORR` returns 0 when a top virtuality is below m_W + m_b.
- MadEvent's `SMATRIX` decides at the first phase-space point of each job
  which helicity configurations are non-zero (`GOODHEL`), and skips the
  others afterwards. If that first point falls where `CORR` = 0, every
  helicity is zero, and the whole job contributes nothing.
- The caching is now disabled in the modified matrix elements, so all 16
  helicities are always summed (see Fixes below). With that change, the 2010
  singlet result rises from 1.968 pb to 2.212 pb, and the octet from
  7.068 pb to 7.662 pb (`IGRN INR ITR IKF` = 1 0 1 1).

This is not a MadEvent bug. The caching assumes that a helicity which
vanishes at one point vanishes everywhere. That holds for ordinary matrix
elements, but the `CORR` = 0 guard of the modification breaks it.

Singlet channel, no K factor, W window applied:

| | 2010 MadEvent | 2015 BASES |
|---|---|---|
| ITR=0 | 1.782 | 1.782 |
| ITR=1, original code | 1.726 | 1.881 |
| ITR=1, fixed (all helicities summed) | 1.940 | 1.881 |

Integrator-independent estimate of σ(ITR=1)/σ(ITR=0), as the mean of the
ratio over unweighted ITR=0 events: 1.044 ± 0.008 (2015 events) and
1.052 ± 0.015 (2010 events). A large BASES run gives 1.055 ± 0.001.

The 2015 result does not depend on the cut-off `MWCUT1 = MW + δ` near the
t → bW threshold (δ = 1 GeV … 0.001 GeV changes σ by less than 0.2%).

**Still open:** after the fix, MadEvent is about 3% above BASES
for `ITR=1`, which corresponds to a ratio of 1.089. The reweighting estimates
favour the BASES value. Followed up in #11.

## Fixes to the 2010 code

- `ppblvblv_Grn_v42/GrnFnc_blvblv/matrix_8_uxu_mu+vmmu-vmxbbx.f` (2026-10,
  #9): the colour amplitude `JAMP(1)` was computed before the label
  `100 CONTINUE`. With `INR=0`, the jump `IF (INR.EQ.0) GOTO 100` skipped it,
  so the ū u → … subprocess gave no contribution. This removed about half of
  the u-type qq̄ channel. The two lines were moved after the label, as in the
  other subprocesses. Runs with `INR=1` were not affected, and neither was
  `blvbjj`. The 2010 numbers above were obtained with the fix. The earlier
  smoke-test values with `INR=0` (7.14 and 8.62 pb) were affected.
- `GrnFnc_*/matrix_*.f`, all 12 modified matrix elements of `blvblv` and
  `blvbjj` (2026-10, #9): `SMATRIX` now always sums all helicities. Before,
  it kept only those found non-zero at the first phase-space point. With
  `ITR=1` and `INR=0`, `CORR` makes the whole amplitude vanish where a top
  virtuality is below m_W + m_b. If a job's first point fell there, the whole
  job contributed nothing. This made the cross sections with `ITR=1 INR=0`
  about 8% too low in our runs. Whether the runs of 2010 were affected
  depends on their random points. Runs with `ITR=0` or `INR=1` were not
  affected, because the amplitude does not vanish there.
